## 1. 지금까지 어떻게 왔나

베이스라인 0.51645 → **0.164770**. 도약이 두 번 있었습니다.

### 도약 1 — 사전학습 가중치가 안 실리고 있었다 (0.51645 → 0.35361)

설정 두 곳이 잘못돼 UNet 본체가 초기화 상태로 학습되고 있었습니다.

| 설정 | 잘못된 값 | 고친 값 |
|---|---|---|
| `only_reload_modules` | `"model"` 누락 | `"model"` 포함 |
| `add_act_time_emb` | `False` | `True` |

두 번째가 특히 안 보였던 이유 — `add_act_time_emb: False`면 `time_embed_dim`이 1280 대신 640으로 잡히면서 모든 ResBlock의 `emb_layers` 모양이 어긋나는데, 로딩이 `strict=False`라 **모양 안 맞는 텐서를 조용히 건너뛰고 예외 없이 지나갑니다.** 로그에는 "로드 완료"만 찍힙니다.

**둘 다 고쳐야 합니다. 하나만으로는 안 됩니다.** 지금 설정은 `configs/train/pretrained_unet_6k.yaml`에 들어 있습니다.

### 도약 2 — 뽑는 게 아니라 고르는 것 (0.35361 → 0.164770)

**평가용 액션이 문제에서 입력으로 주어집니다.** 그래서 `submission_kit`의 채점 모듈을 직접 돌리면 **제출 전에 Action(점수의 40%)을 샘플별로 정확히 계산**할 수 있습니다.

시드와 guidance만 바꿔 영상을 여러 벌 만들어놓고, 216개 샘플마다 Action이 가장 낮은 것을 골라 조립합니다. 후보를 추가하면 각 샘플의 최솟값은 내려가거나 유지될 뿐 절대 올라가지 않으므로 구조적으로 안전합니다.

```
후보 하나하나의 Action    0.437 ~ 0.466   (19벌이 전부 고만고만)
그중 최고를 통째로 제출         총점 약 0.35
19벌을 샘플별로 섞은 것         총점 0.164770
```

영상은 **통째로** 고릅니다. 한 영상 안에서 프레임을 섞거나 이어붙이는 일은 없고 재인코딩도 안 합니다. 최종 CSV는 공식 `make_submission_csv.py`가 만듭니다.

**단, 이 방향은 1시간 제한에 막혀 있습니다.** 위 경고 참조.

## 2. 역할 분담

### 담당 A — 학습 축: 체크포인트 스텝 수와 액션 조건화

**핵심 사실부터 — 체크포인트가 6000 하나뿐입니다.** (2026-08-06 22:40 실물 확인)

```
epoch=1-step=6000.ckpt    5.75GB    ← 이거 하나
```

설정상 2000·4000도 있어야 하고 10k 학습의 8000·10000도 있어야 하는데, **08-06 오전 포드를 잃으면서 전부 사라졌습니다.** 자세한 건 [체크포인트.md](체크포인트.md).

**그래서 스텝 곡선을 공짜로 찍는 건 불가능합니다.** 다른 스텝을 보려면 학습을 다시 해야 합니다.

```
              Action 가중    DINO/Video     총점       체크포인트
2000스텝       0.16338       0.11921       0.28259    ✗ 없음
4000스텝          ?             ?             ?       ✗ 없음
6000스텝       0.16194       0.11993       0.28187    ✓ 있음
10000스텝      0.16596          ?             ?       ✗ 없음
```

기록에 남은 세 점으로 곡선을 맞추면 **총점 최적이 약 4,530스텝, 6000 대비 예상 이득 0.00037**입니다. 학습을 늘리면 Action은 좋아지는데 **DINO/Video는 나빠져서**(0.11921 → 0.11993) 최적점이 앞으로 당겨집니다.

**A-1. 스텝 곡선만 보려고 따로 학습하지 마세요**

| | 얻는 것 | 시간 | 비용 |
|---|---|---|---|
| 백본→4000 단독 | 4000 한 점 | 5.3시간 | **$2.4** |
| 백본→6000, 2000마다 저장 | 세 점 | 8시간 | **$3.6** |
| **A-2에 얹기** | **세 점 + action_shift 결과** | 8시간 | **$0 추가** |

**잔액이 $6.42인데 예상 이득이 0.00037입니다.** 앞의 두 개는 예산의 절반을 여기에 쓰는 셈이라 말이 안 됩니다.

⚠ **6000 체크포인트에서 이어서 학습하면 4000이 안 됩니다.** 7000·8000이 되지 되감기는 안 됩니다. 게다가 `save_only_unet: True`, `save_weights_only: True`라 옵티마이저 상태가 없어 제대로 된 resume 자체가 안 됩니다. 4000짜리 모델은 반드시 **백본에서 새로** 4000스텝을 돌려야 나옵니다.

**A-2. 액션을 한 칸 밀어 넣기 — 이게 본 과제입니다 (코드 준비 완료)**

홀드아웃 정답 영상에서 화면 변화량과 액션 변화량의 시차 상관이 lag 0에서 0.410, **lag +1에서 0.537**입니다. 구동 지연으로 화면이 액션보다 한 프레임 늦는데, `action_embed`가 프레임마다 독립이라 모델이 스스로 못 당겨옵니다.

`patch_shift_orig.py`가 원본 소스 4개 파일에 `action_shift`를 넣습니다. **기본값 0이면 원본과 비트 단위로 동일**하고 검증까지 끝냈습니다. 설정 한 줄 바꾸고 학습만 돌리면 됩니다.

**이 학습 한 번이 스텝 곡선까지 같이 줍니다.** 지금 설정이 이미 `every_n_train_steps: 2000`이라 **아무것도 안 바꿔도** 2000·4000·6000 세 개가 나옵니다. 끝나고 셋을 추론해보면 (어려운 60개 29분 $0.21씩) 곡선이 찍힙니다.

⚠ **디스크가 딱 맞습니다.** 5.75GB × 3 = 17.25GB, 볼륨 여유 22GB. `every_n_train_steps`를 500으로 낮추면 12개 69GB가 되어 **4번째 저장에서 디스크가 차고 8시간짜리 학습이 3시간에 죽습니다.** 2000 그대로 두세요.

### 담당 B — 파라미터 축: 추론 설정과 모델 설정

**B-1. 추론 파라미터 스윕 (학습 불필요, 제일 급함)**

1시간 제한이 확정되면 **한 벌을 최대한 좋게** 만들어야 합니다. 그런데 안 재본 게 많습니다.

| 파라미터 | 현재 | 상태 |
|---|---|---|
| `unconditional_guidance_scale` | 1.0~3.0 | 완료 (0.7~3.0). 개별 최선은 **1.0** |
| `ddim_steps` | 25 | **한 번도 안 해봄** ← 최우선 |
| `timestep_spacing` | uniform_trailing | **안 해봄** |
| `batch_size` | 4 | **안 해봄.** 48GB 중 17.5GB만 사용 |
| `eta` | 0.0 | 완료. 1.0은 1.8배 느림, VRAM 2배 |

`ddim_steps`가 품질과 시간을 동시에 정합니다. 50으로 올리면 한 벌이 좋아지고, 15로 내리면 예산 안에 두세 벌이 들어갑니다. **어느 쪽이 이기는지 모릅니다.**

`batch_size`는 순수 속도입니다. 96GB 카드에서 16까지 올릴 수 있으면 같은 1시간에 훨씬 많이 들어가고, 그게 곧 후보 수입니다.

어려운 60개로 스윕하면 한 번에 29분 $0.21입니다.

**B-2. 모델 설정 중 안 건드린 것**

`configs/train/pretrained_unet_6k.yaml`에 손 안 댄 값들이 있습니다.

| 설정 | 현재 | 왜 볼 만한가 |
|---|---|---|
| `action_dropout_prob` | `0.0` | **액션 CFG의 스위치.** 아래 설명 |
| `use_ema` | `False` | 확산 모델에서 EMA는 보통 표본 품질을 올립니다. 미검증 |
| `uncond_prob` | `0.05` | 이미지 조건 드롭 확률 |
| `dropout` | `0.1` | |
| `use_dynamic_rescale` / `base_scale` | `true` / `0.7` | |

**`action_dropout_prob`가 특히 중요합니다.** 지금 샘플러가 조건부·무조건부 양쪽 모두 `dropout_actions=False`로 호출합니다. 즉 **guidance를 올려도 액션 조건이 전혀 증폭되지 않습니다.** 증폭되는 건 이미지 조건뿐이에요. 이 값을 0보다 크게 줘서 "액션 없음" 임베딩을 학습시키고 추론에서 무조건부 분기의 액션을 빼면, "명령대로 움직여라"를 증폭할 수 있습니다. 조건부 확산 모델의 표준 방법인데 지금 빠져 있습니다.

**B-3. 백본 변경 — 하기 전에 이것부터 확인하세요**

현재 백본은 `DynamiCrafter_512`(10.4GB)이고 대회 README가 직접 받으라고 지시한 모델입니다.

바꾸시려면 네 가지를 먼저 확인해주세요.

1. **라이선스** — 규칙상 "공식적으로 가중치가 공개된 사전학습모델 중, 상업적 또는 비상업적 이용이 허용된 라이선스(MIT, Apache 2.0, CC BY, CC BY-NC)"만 됩니다. API로만 접근 가능한 모델은 불가입니다.
2. **추론 시간** — 지금도 1시간 제한이 빠듯합니다. **백본이 커지면 그것만으로 실격 사유**가 됩니다. 후보 모델의 추론 속도를 먼저 재보세요.
3. **재학습 필요** — 백본을 바꾸면 액션 조건화를 처음부터 다시 붙이고 전체를 다시 학습해야 합니다. 8시간 $3.6, 그런데 잔액이 $6.42입니다.
4. **15일** — 위 셋을 다 통과해도 남은 기간에 끝날지 냉정하게 보세요.

**막지는 않겠습니다만, B-1과 B-2를 먼저 끝내고 시간이 남으면 손대는 순서를 권합니다.** B-1은 하루면 되고 1시간 제한에 직접 대응합니다.

**B-4. 여유 있으면 — 액션이 지나가는 통로 바꾸기 (천장이 제일 높음)**

**이 대회는 텍스트를 안 씁니다.** 그런데 UNet의 텍스트용 크로스어텐션(77토큰 × 1024차원)이 **사전학습된 채로 놀고 있습니다.** 여기에 액션 토큰을 넣는 겁니다.

| | 지금 (시간 임베딩에 더하기) | 크로스어텐션 |
|---|---|---|
| 공간 정보 | **없음** — 화면 전체에 같은 값 | 위치마다 다르게 반응 |
| 시간 정보 | **없음** — 프레임마다 독립 | 16스텝 전체 참조 |

전에 시간축 어텐션을 새로 붙였다가 실패했습니다. 0으로 초기화한 층이 6,000스텝 뒤에도 기존 신호의 0.23%였습니다. 학습률 1e-5에서 새 모듈이 안 깨어난 겁니다. **9시간 40분 태우고 결론이 안 났습니다.** 텍스트 자리를 쓰면 **이미 학습된 어텐션을 재활용**해서 새로 배울 게 `linear(6,1024)` 하나뿐이라 그 실패를 구조적으로 피합니다.

### 둘 중 누구든 30분이면 되는 것

**생성할 때 0번 프레임을 입력 이미지로 갈아끼우기.** 정답 영상의 0번 프레임은 입력 이미지와 사실상 같습니다(차이 1.575, 마지막 프레임은 11.434). 그런데 우리 생성 영상은 0번부터 3.487 어긋나 있습니다. 다 만든 영상을 나중에 고치면 재인코딩 손실이 이득의 12배라 손해지만, **생성 시점에 넣으면 인코딩이 한 번뿐이라 공짜**입니다.

## 3. 왜 두 방향 다 액션을 겨냥하나

점수의 60%가 Action인데 뭘 해도 잘 안 내려갑니다. 코드에 이유가 있습니다.

**액션이 프레임마다 독립적으로 들어갑니다.** `action_embed`가 `nn.Linear`라 마지막 차원에만 작용합니다. 16스텝 시퀀스를 넣어도 각 프레임이 서로를 못 보고 프레임 번호도 모릅니다. 3번과 10번 프레임이 같은 관절값이면 **완전히 같은 임베딩**이 나옵니다. 모델이 "팔이 어디 있는지"만 알고 **"얼마나 빨리 어디로 가는 중인지"를 모릅니다.**

게다가 그 임베딩을 시간 임베딩에 더해서 **화면 전체에 똑같이 곱해지는 상수 하나**로 씁니다. "그리퍼를 왼쪽으로 3cm"를 전달하는 통로치고 너무 좁습니다.

| 시간축 액션 어텐션 | 새 모듈이 안 깨어남. 재시도 시 0 아닌 초기화 + 액션 모듈만 lr 1e-3 + 2000스텝 중단판정 |

| 후보 타겟 샘플 선정 지표 | **무예측.** 순위 상관 −0.092, 무작위와 동일 |
| eta 1.0 | 이득은 있으나 1.8배 느림, VRAM 2배 |

**후보는 "잘 만드는" 게 아니라 "다르게 틀리게" 만들어야 합니다.** 후보를 하나씩 빼며 총점 악화를 재봤더니, guidance 1.0짜리가 개별 Action 0.4369로 최고인데 기여도는 하위였고, guidance 3.0짜리가 0.4634로 최하위인데 기여도가 최고였습니다. 개별 품질이 좋은 후보는 다른 후보들과 **같은 샘플에서 같이 틀려서** 새로 이겨줄 자리가 없습니다. (단 1시간 제한이 확정되면 이 결론이 뒤집혀 개별 1위인 1.0을 써야 합니다.)

## 5. 협업 규칙

- **시드 구간을 반드시 나눌 것.** 겹치면 같은 영상을 두 번 만드는 셈입니다.

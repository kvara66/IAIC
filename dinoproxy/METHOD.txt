DINO 대리 모델 조사 - 방법론 전체
2026-08-11 / 검증용. 한 줄씩 대조해 보실 수 있게 실제 로직을 적었습니다.


================================================================
0. 전체 흐름
================================================================

    1  채점기 코드를 읽어 DINO 전처리 로직을 알아낸다
    2  그 로직을 그대로 재구현하고, 원본과 수치가 같은지 증명한다
    3  이미지 쌍 300~1200개를 만든다 (1단계 전처리까지 끝낸 상태로 저장)
    4  같은 쌍에 모델 5개를 각각 돌려 프레임별 코사인 유사도를 뽑는다
    5  DINO 가 매긴 값과 후보가 매긴 값의 상관관계를 낸다
    6  1위가 우연이 아닌지 부트스트랩으로 검정한다
    7  설정을 바꿔가며 순위가 흔들리는지 확인한다

핵심 원칙 두 가지
    - 모든 모델이 반드시 같은 이미지를 본다 (코드로 강제)
    - 어떤 판단이든 재봤을 때 틀리면 그 자리에서 멈춘다 (검증 내장)

1. 채점기 전처리 로직을 어떻게 알아냈나
================================================================

읽은 파일: open/submission_kit/feature_csv_utils.py

알아낸 것

  373~374행   dino_model_name = "vit_small_patch14_dinov2.lvd142m"
              dino_model = load_dino_model(device, dino_model_name, pretrained=True)
  196~202행   load_dino_model 은 timm.create_model(name, pretrained=True, num_classes=0)
              -> 킷 내부 체크포인트가 아니라 timm 공개 가중치다

  375행       dino_image_size = resolve_dino_image_size(model, requested_size=0)
  252~266행   requested_size <= 0 이면 model.patch_embed.img_size[0] 을 반환
              -> DINO 는 518. 224 가 아니다

  make_submission_csv.py 31~33행
              target-height 320, target-width 512, pad 기본값 True

리사이즈는 두 단계다

  1단계 preprocess_video (36~70행)
      video_tensor = torch.from_numpy(v).float().permute(0,3,1,2) / 255.0
      scale = min(target_height/height, target_width/width)
      resized_h = max(1, round(height*scale))
      resized_w = max(1, round(width*scale))
      F.interpolate(..., mode="bilinear", align_corners=False)
      pad_top = (target_height - resized_h) // 2      나머지는 pad_bottom
      pad_left = (target_width - resized_w) // 2      나머지는 pad_right
      F.pad(..., value=0.0)
      video_tensor = (video_tensor - 0.5) * 2.0        -> [-1,1]

  to_eval_uint8 (105~108행)
      clamp(-1,1) 한 뒤 ((x+1)/2*255) 로 uint8 복원
      * 이 uint8 왕복이 양자화를 넣는다. 빼면 채점기와 값이 달라진다

  2단계 _resize_pad_frame_batch (238~249행)
      frames = frames.float() / 255.0
      scale = min(size/height, size/width)
      같은 방식으로 리사이즈 + 중앙 정렬 F.pad(value=0.0)

  extract_dino_features (300~316행)
      frames = _resize_pad_frame_batch(frames, image_size, pad_value=0.0).to(device)
      frames = (frames - IMAGENET_MEAN) / IMAGENET_STD
      배치 32 로 모델 통과
      출력이 3차원이면 [:, 0] 즉 CLS 토큰

  중요: 2단계는 [0,1] 공간에서 0 으로 패딩한 "뒤에" 정규화한다.
        순서를 바꾸면 검은 여백이 (0-mean)/std 가 아니라 0 이 되어 값이 달라진다.

기하학적으로 무슨 일이 일어나는가

      원본 480x640 (비율 0.750)
        1단계  scale = min(320/480, 512/640) = 0.6667
               -> 320x427, 좌우에 42/43 검은 여백  = 320x512   비율 0.749
        2단계  scale = min(518/320, 518/512) = 1.0117
               -> 324x518, 상하에 97/97 검은 여백  = 518x518   비율 0.750

      어디서도 늘리거나 찌그러뜨리지 않는다. 비율은 보존되고 여백만 붙는다.
      최종 내용 면적 = 0.834 x 0.625 = 52%. 나머지 48% 가 검은색이다.

3. 이미지 쌍을 어떻게 만들었나
================================================================

공통 규칙
    - 쌍의 양쪽 모두 1단계 전처리(320x512)까지 끝낸 뒤 PNG 로 저장한다.
      1단계는 모델과 무관하므로 한 번만 하면 되고, 이러면 양쪽이 반드시 동일하게 처리된다.
      extract 단계는 2단계(모델별 입력 크기)만 한다.
    - PNG 는 무손실이라 저장/읽기로 값이 안 바뀐다 (4가지 해상도에서 0.000e+00 확인).
    - 파일명이 곧 pair_id 이고, gt/ 와 pred/ 의 파일명이 하나라도 다르면 실행이 중단된다.

실험 1  무관한 학습 영상 무작위 (dinopairs)
    출처   /workspace/open/data/train 의 mp4 11,132개 (약 100만 프레임)
    방법   무작위로 영상 두 개, 각각 무작위 프레임 한 장씩 뽑아 짝짓기. 300쌍.
           같은 영상의 같은 프레임이 걸리면 다시 뽑음.
    추가   검산용 동일쌍 20개 (같은 프레임을 양쪽에) -> 모든 모델에서 거리 0 이어야 함
    seed   0

실험 2  진짜 정답 vs 우리 예측 (pairs_gt)
    출처   /workspace/holdout/gt/*.npy    정답 영상 20개, (16,480,640,3) uint8
           /workspace/runs/ck667/videos/*.mp4   같은 장면의 우리 생성물 20개, 320x512
    방법   같은 sample_id 의 같은 프레임 t 끼리 짝짓기. 20 x 16 = 320쌍.
    특징   정답은 480x640 이라 1단계에서 좌우 패딩이 붙고, 생성물은 이미 320x512 라 통과.
           이게 채점기가 하는 것과 완전히 같다.

실험 3  우리 예측 vs 우리 예측 (pairs_gen)
    출처   runs/sub_ck667/videos, runs/sub_g25/videos   각 216개
    방법   같은 sample_id, 같은 프레임을 두 설정에서 하나씩. 무작위 300쌍.
    근거   "정답" 은 진짜 정답일 필요가 없다. 두 이미지를 비교하는 두 자리일 뿐이다.

실험 4  실험 3 을 확대 (pairs_big) - 확정 근거
    출처   sub_ck667, sub_g25, final_g10s50, final_static  각 216개
    방법   (장면 216 x 프레임 16 x 설정쌍 6) = 조합 20,736개에서 중복 없이 1,200개 추출
           설정쌍 6가지 = 4벌에서 2개 고르는 모든 조합
    결과   1,200쌍, 고유 장면 214개
    seed   0

주의: 실험 2 는 정답 npy 가 20개뿐이라 독립 표본이 20개다. 확정 근거로는 못 쓴다.
      그래서 실험 4 로 확정했다.

4. 특징 추출 로직
================================================================

파일: dinoproxy/extract.py, common.py

모델별로 다르게 한 것: 입력 크기와 정규화 상수
모델별로 똑같이 한 것: 기하 처리 (비율유지 리사이즈 + 중앙정렬 + 검은패딩)

    모델            timm 이름                              입력   차원   정규화
    dino(기준)      vit_small_patch14_dinov2.lvd142m       518    384   ImageNet
    clip_l14        vit_large_patch14_clip_224.openai      224   1024   CLIP
    clip_b16        vit_base_patch16_clip_224.openai       224    768   CLIP
    siglip_b16      vit_base_patch16_siglip_224            224    768   (0.5,0.5,0.5)
    mae_b16         vit_base_patch16_224.mae               224    768   ImageNet

입력 크기는 채점기와 같은 함수로 결정한다
    model_input_size(model, 0) -> model.patch_embed.img_size[0]

정규화 상수는 각 모델의 pretrained_cfg 에서 읽는다
    왜: 채점기가 DINO 에 ImageNet 을 쓰는 건 dinov2 의 cfg 값과 같아서 맞는 것이다.
        SigLIP 에 ImageNet 을 강제하면 학습 때 본 적 없는 입력을 주는 셈이라
        "판단력" 이 아니라 "얼마나 망가지나" 를 재게 된다.

처리 순서 (채점기 300~316행과 동일)
    2단계 리사이즈/패딩 -> (x - mean)/std -> 모델 통과 -> 풀링

특징
    timm.create_model(name, pretrained=True, num_classes=0) 의 출력
    3차원이면 CLS 토큰([:,0]), 4차원 이상이면 공간 평균 (채점기와 동일)

배치
    기본 16. 배치 크기는 값에 영향이 없다는 것을 실측으로 확인
    (batch=1 과 batch=16 의 상관계수가 소수점 6자리까지 동일)

5. 점수 계산
================================================================

    코사인 유사도  cos_sim  = F.cosine_similarity(정답특징, 예측특징, dim=-1)
    코사인 거리    cos_dist = 1 - cos_sim        (낮을수록 닮음)

6. 상관관계 분석
================================================================

파일: dinoproxy/corr.py

    Pearson    두 값이 나란히 커지고 작아지는 정도. 로스로 쓸 거면 이쪽이 중요
    Spearman   순위만 보고 재는 상관. 순위에 Pearson 을 적용한 것
               둘이 크게 다르면 관계가 비선형이라는 뜻

    scipy 없이 numpy 만으로 직접 계산했고, numpy.corrcoef 와 대조해 확인했다 (차이 1.1e-16)

    검산쌍(identity)은 상관계수 계산에서 뺀다. 거리 0 이 한 점에 몰려 결과를 왜곡하므로.

추가로 본 것

    구간별 상관계수   DINO 거리를 사분위로 나눠 각 구간 안에서도 순위가 유지되는지
    Kendall tau       두 쌍을 골랐을 때 같은 순서로 판단할 확률로 환산
    환산오차          후보 값을 DINO 눈금에 맞게 직선 변환한 뒤 남는 평균 오차

7. 통계 검정
================================================================

파일: dinoproxy/compare.py, robust.py

부트스트랩
    같은 쌍들을 복원추출로 다시 뽑아 상관계수를 다시 계산. 10,000회.
    매번 어느 모델이 1등인지 세면 "1위가 진짜 1위일 확률" 이 나온다.
    두 상관계수가 같은 DINO 값을 공유하므로 쌍 단위로 함께 리샘플한다.

군집 부트스트랩 (중요)
    실험 2, 4 는 한 장면에서 여러 프레임을 뽑았다. 같은 장면의 프레임들은
    서로 강하게 닮아 있어 독립 표본이 아니다.
    프레임 단위로 리샘플하면 신뢰구간이 실제보다 좁게 나온다.
    그래서 "장면" 단위로 다시 뽑았다.
        실험 4: 쌍 1,200개지만 독립 군집 214개로 계산

반쪽 나누기
    쌍을 무작위로 절반씩 갈라 각각 순위를 매기고, 두 절반이 같은 1위를 내는지. 2,000회.

분포 건전성 검사
    범위       DINO 거리의 최소~최대 폭이 좁으면 상관계수가 불안정하다
    봉우리 계수 Sarle 의 bimodality coefficient. 0.555 를 넘으면 봉우리가 둘일 수 있고,
               그러면 두 덩어리를 갈라놓기만 해도 상관계수가 높게 나와 순위가 무의미해진다.
               실험 4 실측 0.552 로 단봉 -> 부풀림 없음

유일한 예외의 해석
    SigLIP 학습 상수는 (0.5,0.5,0.5) 인데 ImageNet 을 강제하면 학습 때 본 적 없는
    입력을 주는 것이다. 판단력이 아니라 붕괴를 재는 셈이다.
    증거: CLIP 은 자기 상수가 ImageNet 과 거의 같아 영향이 없다 (.5723 -> .5725).
          SigLIP 만 .6341 -> .2488 로 무너진다.
    실제로 로스에 붙일 때 SigLIP 에 ImageNet 을 먹일 이유가 없다.

해상도 관련 참고
    DINO@518 과 DINO@224 의 상관계수가 0.8396 이다.
    같은 모델도 해상도만 바꾸면 이만큼 달라진다는 뜻이라,
    입력 크기가 다른 모델끼리 비교할 때 감안해야 한다.
    다만 해상도를 맞춰도, 후보를 518 로 올려도 순위는 같았다.

    메모리 연속성              채점기 False, 재구현 True
    같은 텐서를 두 번 통과      0.000e+00

값이 아니라 메모리 배치가 달라서 GPU 가 다른 커널을 골랐고, 부동소수점 덧셈 순서가
달라진 것이다. 로직 오류가 아니며, 우리가 구분하려는 모델 간 차이(0.08)의 1/2000 이다.

11. 진행 중 발견해서 폐기한 것 (참고)
================================================================

    번호 영역 자동 탐지 실패
        생성 영상에 흰 상자/로봇 팔 같은 밝은 물체가 많아 "밝은 픽셀" 기준이
        화면의 71% 를 글자로 잡았다. 그 상태로 잰 값은 무효라 폐기하고,
        고정 좌표 + 눈으로 확인하는 방식으로 바꿨다.
        (최종적으로는 번호 없는 원본 영상을 확보해 마스킹 자체가 불필요해졌다)

    번호 오버레이의 출처
        생성 영상 216개를 하나로 이어붙인 파일에만 있던 것으로, 결과 확인용으로
        붙였던 것이다. 원본 mp4 에는 없다.

    tar 스트림 오염
        전송 명령에 du 출력이 섞여 아카이브가 깨졌다. 무결성 검사로 잡아 다시 받았다.

    argparse 누락
        코드에서 쓰는 옵션이 정의에 없었다. 실행 전 정적 검사로 발견해 고쳤다.


================================================================
11-1. 채점 공식 확인 (2026-08-11)
================================================================

대회 평가 페이지에서 직접 확인했습니다.

    Score = 0.3 x DINO Component + 0.3 x Video Feature Component
            + 0.4 x Action Component

    DINO Component 정의
      "생성 영상의 프레임 단위 시각적 특징이 정답 데이터와 얼마나 유사한지 평가"

    계산 방식
      "공식 제출킷(submission_kit)을 통해 추출된 feature 를 바탕으로
       정답 feature 와의 거리를 계산(Cosine Distance)합니다"

프레임 단위인 것도 코사인 거리인 것도 공지와 일치하므로,
이 조사에서 쓴 비교 기준(프레임별 코사인 거리)이 옳습니다.
